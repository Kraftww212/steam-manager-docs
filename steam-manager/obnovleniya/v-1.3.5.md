# V 1.3.5

Переписана покупка на Торговой площадке под оба отображения Steam (стакан и отдельные лоты), исправлен разбор ответов Steam и подтверждение в Steam Guard на массовых прогонах, добавлен опциональный подробный лог по каждому аккаунту.

### Торговая площадка

1. У Steam два разных отображения предмета — стакан ("ордер на покупку") и таблица отдельных лотов ("Купить"). Раньше автобай на ТП умел покупать только через стакан; для предметов, которые продаются отдельными лотами (например, скины CS2), это либо зависало, либо покупало не то. Теперь шаг цепочки "Покупка на ТП" сам определяет, какое отображение у предмета, и покупает через него — включая гибридные предметы (кейсы, у которых есть оба варианта одновременно).
2. Исправлен разбор стакана: Steam обновил формат ответа на двойную обёртку, из-за которой цена ошибочно считалась "пустой" на каждом запросе — это и было причиной лавины лишних запросов и ошибок HTTP 429 при покупке кейсов.
3. Когда лоты на витрине заканчиваются (их разобрали другие аккаунты в этом же прогоне), аккаунт больше не сдаётся сразу — он обновляет список ещё не проданных лотов и пробует снова, по кругу, пока не купит или не закончатся попытки.
4. Задание Community Leader "Купить на ТП" тоже переведено на новый механизм покупки — старая версия разбирала HTML-страницу по устаревшей вёрстке Steam и всегда падала с ошибкой "no listing ID found".

### Подтверждение в Steam Guard

5. Переписан цикл подтверждения покупки: раньше при ошибке "Ордер создан, требуется подтверждение" повторный запрос уходил не с тем идентификатором, который ждёт Steam, — подтверждение никогда не проходило. Теперь используется правильный идентификатор, а сообщение об ошибке показывает точную причину (сколько раз подтверждение не нашлось в мобильном списке / не приняли / Steam ответил лимитом запросов), а не общую фразу без деталей.
6. Запросы списка мобильных подтверждений теперь идут через общий "шлюз": не больше нескольких одновременно, с паузой между стартами и общей задержкой после HTTP 429. Раньше сотни аккаунтов, ожидающих подтверждения одновременно, забивали Steam запросами и получали 429 разом на всех попытках.

### Отчёт цепочки действий

7. Исправлена ошибка сборки, из-за которой в собранном приложении статистика шагов цепочки могла "слипаться" в одну на все шаги сразу (например, отчёт показывал "15/15" вместо честных "5/5" на каждом из 3 шагов, а в результатах одного шага попадались строки другого). Причина — настройка обфускатора, ломавшая объекты внутри стрелочных функций; добавлена защитная проверка, чтобы это не повторилось незаметно при следующей сборке.

### Подробный лог по аккаунтам (новое)

8. В настройках появилась опция "Подробный лог действий" (по умолчанию выключена). При включении софт пишет на диск, что происходит с каждым аккаунтом: шаги цепочек, гифт-коды, лут, добивка баланса, трейды, покупка/продажа на ТП, задания Community Leader. Формат экономный — один файл в день на все аккаунты, а не по файлу на аккаунт, с автоматической очисткой записей старше 14 дней, так что подходит и для 5000+ аккаунтов.
9. Там же можно сформировать текстовый отчёт по выбранным аккаунтам и/или группе за произвольный период: сколько событий всего, сколько успешных/неуспешных и полная хронология по каждому аккаунту.
