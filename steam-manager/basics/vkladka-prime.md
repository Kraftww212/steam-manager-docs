# Вкладка "Prime"

Конвейер «раскид предметов → продажа → покупка игры» на много аккаунтов. Классический сценарий: с одного аккаунта-источника разослать предметы получателям, каждый получатель продаёт их на ТП и на вырученные деньги покупает CS2 Prime (sub 54029) или любую другую игру. Доступно в Premium.

***

### Основные элементы

* **Источник** — аккаунт, с которого отправляются предметы. Должен быть онлайн, с загруженным инвентарём и `identity_secret` (трейды подтверждаются автоматически).
* **Получатели** — список аккаунтов справа: поиск, выбор по группам, чекбоксы. Групповой фильтр сайдбара тоже действует.
* **Без Prime** — чекбокс над списком получателей: скрывает аккаунты, у которых Prime уже есть, чтобы не покупать второй раз. Включён по умолчанию, запоминается.
* **Игра** — Sub ID покупки. По умолчанию 54029 (CS2 Prime), можно указать другой пакет или несколько.
* **Стратегия продажи** — Мин -1 / Автобай / Своя цена (см. вкладку Инвентарь) или **Только раскид** — предметы разлетаются по получателям без продажи и покупки.
* **Потоки** — берутся из настроек («Кол-во одновременных входов»).

***

### Режимы выбора предметов

{% tabs %}
{% tab title="Ручной выбор" %}
Загрузите инвентарь источника, отметьте предметы и укажите «шт/акк» — сколько штук уйдёт каждому получателю. Предметы раздаются по порядку: лишним получателям не хватит, о чём софт предупредит.
{% endtab %}

{% tab title="Конфиг" %}
Сохранённые наборы: список предметов с количеством, стратегия, цена, игра. Создаёте один раз, дальше выбираете из списка и жмёте «Запустить». Конфиги можно редактировать и удалять.
{% endtab %}

{% tab title="Автоподбор" %}
Софт сам подбирает наборы предметов под стоимость игры: указываете игры-источники инвентаря, Sub ID, диапазон цен предмета и разброс в процентах, нажимаете «Подобрать». Для каждого получателя формируется свой набор, лишнее никому не уходит.
{% endtab %}
{% endtabs %}

***

### Что делает конвейер

1. Отправляет трейд от источника получателю (большие партии режутся по 200 предметов на оффер) и подтверждает его через Guard.
2. Принимает трейд на получателе, ждёт появления предметов.
3. Выставляет предметы на ТП по выбранной стратегии в валюте получателя, подтверждает листинги.
4. Ждёт продаж и зачисления денег, учитывает холд баланса.
5. Покупает игру. Стоимость игры считается один раз на валюту и кешируется, чтобы не дёргать магазин на каждом аккаунте.
6. Переходит к следующему получателю. Кнопка **Стоп** останавливает именно текущий запуск.

***

### Статус и история

* **Статус** — таблица текущего запуска: этап по каждому получателю (трейд отправлен, продажа, проверка баланса, холд, куплено, ТП закрыта).
* **История** — завершённые связки «источник → получатель» с числом отправленных предметов и фазой. Для каждой записи доступны действия: **Перевыставить** лоты, **Проверить баланс**, **Купить** игру вручную, а также удаление записи.
* При повторном запуске получатели из истории учитываются: завершённые пропускаются, у тех, кто застрял на продаже, продажа продолжается без нового раскида. В режиме «Только раскид» история никого не блокирует.

{% hint style="warning" %}
Получатели должны быть онлайн, с открытой ТП и с `identity_secret`. Аккаунты с закрытой ТП помечаются в истории и пропускаются: продать они не смогут.
{% endhint %}
